# Интерфейс на neo-blessed

## Фабрики компонентов

Компонент — это функция `createX(screen, theme, callbacks)`, возвращающая объект с
методами обновления. Внутри она создаёт виджеты blessed и вешает обработчики клавиш,
но ничего не знает ни о `state`, ни о Telegram.

```js
export function createChatList(screen, theme, { onSelectDialog, onTabChange, onSearchChange } = {}) {
```

Наружу компонент говорит только через колбэки из третьего аргумента. Всё, что нужно
показать, приходит параметрами методов.

## Цвета

- Цвет берётся **только** из активной темы (`getTheme()`, хелперы `fg`, `badge`
  из `src/ui/theme.js`). Хардкод цвета в компоненте — ошибка.
- Именованные цвета (`blue`, `cyan`, `gray`, `white`) не используются: они занимают
  индексы xterm 0–15, которые тема терминала пользователя перекрашивает произвольно.
  Только hex.
- Новый hex-цвет должен после конверсии в xterm-256 давать индекс ≥ 16 и проходить
  контраст WCAG 3:1 с фоном, на котором он рисуется. Это проверяет тест в
  `test/unit.test.js` — он падает, если подобрать цвет неаккуратно.
- Тема добавляется в `themes` в `src/ui/theme.js` через `buildTheme(palette)`, чтобы
  контраст задавался в одном месте, и сразу попадает под тест контраста.

## Пользовательский текст

Любая строка, пришедшая из Telegram (имя, текст сообщения, название чата, имя файла),
перед выводом проходит через `escapeBlessed()` из `src/telegram/formatter.js`.
Иначе фигурные скобки в сообщении будут восприняты как теги разметки и сломают экран.

Разметку Telegram Entities строит `formatMessageText()`; палитра разметки подменяется
темой через `setMessagePalette()` из `app.js` — не из компонента.

## Клавиши и фокус

- Глобальные сочетания (`Tab`, `F1`, `Ctrl+O`, `Ctrl+Q`) регистрируются в `app.js`;
  локальные — внутри своего компонента.
- Модальное окно на время жизни забирает фокус и возвращает его предыдущему владельцу
  при закрытии; `Esc` закрывает модальное окно всегда.
- Новое сочетание клавиш добавляется одновременно в три места: обработчик,
  `helpModal.js` и таблицу горячих клавиш в обоих README.

## Перерисовка

`screen.render()` вызывается после пачки изменений, а не после каждого присваивания.
В обработчиках событий `state` перерисовка идёт один раз в конце.
