# Тесты

## Как устроено

Единственный файл — `test/unit.test.js`, запускается через `npm test`
(`node test/unit.test.js`). Тестового фреймворка нет: `node:assert/strict`,
нумерованные секции в блоках `{ ... }` и `console.log("  ✓ ... tests passed")`
в конце каждой секции.

```js
// 1. Тесты утилит времени
{
    assert.equal(formatFileSize(1024), "1.0 KB");
    console.log("  ✓ time.js tests passed");
}
```

Новая проверка добавляется в существующую секцию по смыслу; новая секция заводится,
только когда появляется новый модуль.

## Что покрывается

Чистые функции без сети и без аккаунта:

- форматирование времени, размеров и длительностей (`utils/time.js`);
- разбор пиров, типы чатов, отображаемые имена (`telegram/entities.js`);
- рендеринг Telegram Entities и экранирование (`telegram/formatter.js`);
- разбор аргументов слэш-команд (`utils/commands.js`);
- запись `.env` и валидация ключей API (`cli/init.js`);
- защита от логина в неинтерактивной среде (`telegram/auth.js`);
- контраст тем по WCAG (`ui/theme.js`);
- конфигурация пакета (`package.json`).

**Не покрывается и покрываться не должно:** сетевые вызовы MTProto, интерактивный
TUI, реальная авторизация. Тест не должен требовать `session.txt`, ключей API или
сетевого доступа — иначе он не запустится ни в CI, ни у нового контрибьютора.

## Правило

Любая новая чистая функция сопровождается проверкой. Багфикс сопровождается тестом,
который падал бы до исправления.

Работа с файловой системой в тестах идёт во временный каталог через
`fs.mkdtempSync(path.join(os.tmpdir(), ...))` и убирается за собой.

## Перед завершением задачи

```bash
npm test
node scripts/check-package.js
```

Обе команды должны отработать зелёными. `npm test` вызывается автоматически
в `prepublishOnly`, так что красный тест блокирует публикацию.
